## BLOCK LEVEL TOOLS

### SCQA Framework
**Category:** Architect / Block Level
**Source:** Barbara Minto, McKinsey & Company

**Purpose:** Frame the strategic problem and response.

| Element | Definition | Question It Answers |
|---------|------------|---------------------|
| Situation | Shared starting point | "What do we all agree on?" |
| Complication | Change or threat | "What's different or at risk?" |
| Question | Issue to resolve | "What must we decide?" |
| Answer | Your response | "What should we do?" |

**When to Use:** Opening of every presentation; framing each major section.

---

### MECE Principle
**Category:** Architect / Block Level
**Source:** McKinsey & Company

**Purpose:** Ensure logical completeness without overlap.

```
Mutually Exclusive = No overlaps between categories
Collectively Exhaustive = No gaps; all aspects covered
```

**Test Your Structure:**
1. Are any ideas duplicated across categories?
2. Is anything important missing?
3. Would a new piece of information have a clear home?

**Common MECE Frameworks:**
- Revenue = Price × Volume
- Customers: New vs. Existing
- Growth: Organic vs. Inorganic
- Time: Past, Present, Future

---

### Hero's Journey / Mentor Model
**Category:** Storyteller / Block Level
**Source:** Joseph Campbell, Nancy Duarte

**Purpose:** Structure the narrative arc with audience as hero.

**Key Insight:** The presenter is NOT the hero. The audience is. You are the Mentor (Yoda, Gandalf).

**Simplified Business Arc:**
1. **Ordinary World** → Current state (Situation)
2. **Call to Adventure** → Challenge appears (Complication)
3. **Tests & Allies** → Evidence and analysis
4. **Ordeal & Reward** → Key insight and solution
5. **Return** → New reality and call to action

---

### Big Idea
**Category:** Storyteller / Block Level
**Source:** Nancy Duarte

**Purpose:** Crystallize the core message in one memorable sentence.

**Formula:**
```
[Point of View] + [What's at Stake] = Big Idea
```

**Requirements:**
- One sentence, ≤20 words
- States an opinion, not just a topic
- Conveys why it matters
- Memorable and repeatable

---

### Plausibility Loop
**Category:** Designer / Block Level
**Source:** Consulting practice

**Purpose:** Plan evidence needed for each claim.

**Process:**
1. List every claim in your argument
2. Identify what evidence would make each plausible
3. Assess what you have vs. what you need
4. Determine visual type for each piece of evidence

```
Claim → Evidence Needed → Data Source → Visual Type → Status
```

## LOOP LEVEL TOOLS

### Deductive Reasoning
**Category:** Architect / Loop Level
**Source:** Classical logic

**Purpose:** Build an airtight chain of logic.

**Structure:**
```
Premise 1 + Premise 2 → Conclusion
"If A is true, and B is true, then C must be true"
```

**Example:**
- AI is transforming every industry
- Our industry is not exempt
- Therefore, we must adapt or become irrelevant

**Best For:** Skeptical audiences, legal/analytical cases, single pivotal insight.

---

### Inductive Reasoning
**Category:** Architect / Loop Level
**Source:** Classical logic

**Purpose:** Group evidence to form a conclusion.

**Structure:**
```
Point A + Point B + Point C → Pattern/Conclusion
"We observe X, Y, Z, therefore..."
```

**Example:**
- Customer satisfaction is declining
- Employee turnover is increasing
- Quality metrics are falling
- Conclusion: Our operational model is failing

**Best For:** Time-pressed audiences, multiple supporting factors, summarizing findings.

---

### Sparklines
**Category:** Storyteller / Loop Level
**Source:** Nancy Duarte

**Purpose:** Map emotional tension across the presentation.

**Concept:** Great presentations oscillate between:
- What Is ↔ What Could Be
- Problem ↔ Solution
- Pain ↔ Relief

**Visual Pattern:**
```
     ╱╲      ╱╲      ╱╲
    ╱  ╲    ╱  ╲    ╱  ╲
───╱    ╲──╱    ╲──╱    ╲──►
```

**Application:** Map your loops to ensure tension rises and falls; avoid monotone delivery.

---

### Contrast
**Category:** Storyteller / Loop Level
**Source:** Presentation best practices

**Purpose:** Create engagement through juxtaposition.

**Contrast Pairs:**
| First | Then |
|-------|------|
| Before | After |
| Problem | Solution |
| Old Way | New Way |
| Risk | Opportunity |
| Them | Us |
| Complexity | Simplicity |

**Usage:** Open loops with the first state, close with the second.

---

### Reveal vs. Headline Strategy
**Category:** Designer / Loop Level
**Source:** Data storytelling practice

**Purpose:** Decide how to disclose data for maximum impact.

| Approach | When to Use | Example |
|----------|-------------|---------|
| **Headline First** | Time-pressed audience, clear conclusion | "Sales grew 40%" → show chart |
| **Progressive Reveal** | Need buy-in, skeptical audience | Show data → "So, what's causing this?" |
| **Dramatic Reveal** | Single shocking data point | Build context → surprise reveal |

## SLIDE LEVEL TOOLS

### Action Titles
**Category:** Architect / Slide Level
**Source:** Consulting practice

**Purpose:** Communicate the insight, not just the topic.

**The "So What?" Test:**
- If your title just describes content → FAIL
- If your title states what the audience should learn → PASS

| ❌ Descriptive | ✅ Action Title |
|---------------|-----------------|
| "Sales Data" | "Sales exceeded target by 15%" |
| "Market Analysis" | "Market will double in 5 years" |
| "Competitive Landscape" | "We're losing to three key competitors" |

**Headline Test:** Could someone understand your argument by reading ONLY titles?

---

### Metaphor
**Category:** Storyteller / Slide Level
**Source:** Communication theory

**Purpose:** Make abstract concepts concrete and memorable.

**Good Metaphors Are:**
- Familiar to the audience
- Visually evocative
- Extended consistently

**Examples:**
| Abstract | Metaphor |
|----------|----------|
| Disruption | "Tidal wave" |
| Silos | "Islands without bridges" |
| Transformation | "Building the plane while flying it" |
| Integration | "One source of truth" |

---

### Data-Ink Ratio
**Category:** Designer / Slide Level
**Source:** Edward Tufte

**Purpose:** Maximize clarity by minimizing non-data elements.

**Formula:**
```
                    Ink used for data
Data-Ink Ratio = ─────────────────────
                   Total ink on chart
```

**Remove:**
- Unnecessary gridlines
- Redundant legends
- 3D effects
- Background colors
- Decorative elements

**Keep:**
- Data points
- Clear labels
- Essential axis markers
- Source citation

---

### Chart Selection Guide
**Category:** Designer / Slide Level
**Source:** Data visualization best practices

| To Show... | Use... |
|------------|--------|
| Change over time | Line chart |
| Part of whole | Pie (≤5), Stacked bar |
| Comparison | Bar chart |
| Correlation | Scatter plot |
| Distribution | Histogram |
| Flow | Sankey, Waterfall |
| Ranking | Sorted horizontal bar |
| Simple KPI | Big number |

## QUALITY TESTS

### The Squint Test
**Level:** Slide
**Question:** If I squint, can I tell what's important?

If yes → Good visual hierarchy
If no → Redesign with clearer emphasis

### The 3-Second Test
**Level:** Slide
**Question:** Can someone grasp the main point in 3 seconds?

If yes → Message is clear
If no → Simplify or split into multiple slides

### The Headline Test
**Level:** Full Presentation
**Question:** Could someone understand the argument from titles alone?

If yes → Strong logical structure
If no → Revise titles to state insights

### The "So What?" Test
**Level:** Slide
**Question:** Does each slide answer "so what?" for the audience?

If yes → Relevant and insightful
If no → Either cut or reframe

### The One Idea Test
**Level:** Slide
**Question:** Does this slide communicate exactly ONE idea?

If yes → Focused and clear
If no → Split into multiple slides
